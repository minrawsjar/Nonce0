# Contracts: Accounts, Pools and Verifiers

> **Solidity 0.8.26, Foundry, via-IR. 97 tests passing.**

Everything Opaque puts on chain: a post-quantum account and its key registry, one USDC pool per note size, the verifier that lets a pool pay out for an eight-note ring, and the directory relays report their health to. There is no owner, admin, pause or upgrade path in any account or registry contract.

## Contracts

### PQKeyRegistry.sol

Holds each account's FORS+C key commitment, the next key's commitment, the use count and the maximum. After registration, **only a valid signature under the account's current PQ key can change that key.** There is no owner, no admin, no pause, no upgrade hatch and no ECDSA guardian: a quantum adversary holding any such fallback would use it to rotate the key to one it controls. `msg.sender` authorises one thing, the first registration. `test_noAddressCanChangeAKeyWithoutAPqSignature` is that claim as a test. Registry actions are domain-separated from user payloads, so a signature for a transfer can never be replayed as a rotation.

### ForsVerifier.sol

Verifies FORS+C signatures on chain with nothing but keccak. Measured with `forge test -vv`:

| | Execution | Calldata | Total tx |
|---|---|---|---|
| `abi.encodePacked` throughout, k=32 a=8 | 981,397 | 148,016 | ~1,150k |
| Scratch buffers, k=32 a=8 | 260,029 | 148,016 | ~429k |
| Scratch buffers, **k=13 a=13** | **167,073** | **93,744** | **~282k** |

The cost was never the hashing. A probe (`test/GasProbe.t.sol`) puts 322 raw keccak calls at 41,004 gas and the same calls built with nested `abi.encodePacked` at 457,475. The verifier lays each preimage out once and rewrites only the fields that change. Accounts use k=32, a=8; `test_cheaperParametersVerifyAndCostLess` shows the verifier already handles k=13, a=13.

### PrivatePool.sol

Holds USDC in one fixed denomination. A deposit records an opaque commitment; a spend checks the ring through its verifier and pays one denomination to the recipient. Two things it deliberately lacks:

- **No `mapping(address => uint256)`.** A balance is the set of notes you hold secrets for. If wallets moved their own tokens, the transfer's `from` would name the spender.
- **No event linking a nullifier to a ring member.** `Spent` names the nullifier and the recipient, both public at settlement, and never the commitment it opened.

The nullifier binds the note secret and the pool, never the recipient. A recipient-dependent nullifier would let one note be spent once per recipient. `test_changingTheRecipientDoesNotMintANewNullifier` pins that.

### AttestedRingVerifier.sol

The RING_8 path. A 1.08 MiB ring proof cannot go on chain, so it is verified off chain and attested. The chain still enforces most of the protocol:

- every ring member is a real deposit (`PrivatePool`);
- the nullifier is consumed exactly once (`PrivatePool`);
- one denomination goes to the bound recipient (`PrivatePool`);
- the attestation carries a valid signature under the attester's current post-quantum key, within its few-time budget (`PQKeyRegistry`).

What moves off chain is one question: does the proof show the spender knows the secret for one of these eight commitments. Each verifier binds its pool's id and denomination.

### SingleNotePqVerifier.sol

The first settlement path: post-quantum and verified on chain, but not anonymous, because it publishes the note secret. That makes a one-shot spend front-runnable, so the pool commits `keccak(recipient, proof, salt)` first and reveals after `COMMIT_DELAY_BLOCKS`. `test_frontRunningTheRevealFails` walks the attack. A pool reports its mode through `capabilities()`, so no interface can present a single-note spend as eight-member anonymity.

### RelayDirectory.sol

Relays announce their endpoint and key commitment, and an operator key reports their health every 10 minutes. The Graph indexes both, and the wallet and the CRE enclave read them back.

## Cross-Language Vectors

`test/fixtures/*.json` are generated in TypeScript by `packages/pq-wallet` and `backend/zk`. The Solidity verifiers are checked against signatures and attestations they had no part in producing: public keys, leaf indices, commitments, scheme ids and full 9,251-byte signatures. Both sides hash the same length-prefixed encoding ([`Canonical.sol`](src/opaque/lib/Canonical.sol)), because a separator that can occur inside a field lets `"a:b" + "c"` and `"a" + "b:c"` hash alike.

## Usage

The account tests import the ERC-4337 interfaces from `packages/pq-wallet`, so install it first.

```bash
npm ci --prefix ../packages/pq-wallet
forge build
forge test
forge test -vv --match-contract ForsVerifier   # the gas numbers above
```

### Deploy

The RPC is named in `foundry.toml`. The key goes into the shell that runs the command, never into a flag, a file in this repository or a chat.

```bash
read -rs PRIVATE_KEY && export PRIVATE_KEY

forge script script/DeployPQStack.s.sol --rpc-url arc_testnet --broadcast     # registry, validator, account, factory, relay directory
ATTESTER=0x… ATTESTER_PK_COMMITMENT=0x… ATTESTER_NEXT_COMMITMENT=0x… \
  forge script script/DeployRingPool.s.sol --rpc-url arc_testnet --broadcast  # one pool and its verifier
```

Run each once without `--broadcast` first and read the addresses. Then record them in `deployments/arc-testnet.json`; `backend/chain/test/deployments.test.ts` checks every one against the chain.

Arc has one USDC in two interfaces: the ERC-20 at `0x3600…0000` with 6 decimals, which the pools hold, and the native currency with 18 decimals, which pays gas. Confusing them is a factor of 10¹².
